# Architecture: PAE map (Giga-style, Sri Lanka only)

Inputs: `replica/01-recon/recon.md`, `replica/01-recon/features.csv`, `replica/01-data/report.md`.
Scope: **Sri Lanka only**. Offline-first PWA. UI in EN / SI / TA.
Date: 2026-11-15.

## 1. Stack

| layer | choice | why |
|---|---|---|
| App | **PWA, Vite + TypeScript** | Installs on any phone without a store, one codebase, fast builds. Decided in wave 0. |
| UI | **Preact + @preact/signals** | 4 KB React-compatible components for panels, sheets and dialogs; signals keep map state and UI in sync without a store library. Matters on low-end Android. |
| Styling | Plain CSS with custom-property tokens from phase 3 | No build-time CSS framework needed; tokens map directly to light/dark/accessible themes. |
| Map | **MapLibre GL JS** | Open source, GPU vector rendering, full style control for the Strava-like roads. |
| Tiles | **PMTiles** via the `pmtiles` JS protocol | One file per layer, no tile server. Online: HTTP range requests. Offline: the same file read from device storage. |
| Basemap | Own `base.pmtiles` for Sri Lanka built with Planetiler (land, water, admin boundaries, place labels) | No Mapbox/third-party basemap (licensed in the original); same toolchain as roads. |
| Roads | `roads.pmtiles` from phase 1B | 340,294 ways, z5–14, 37 MB. |
| Schools | Static `schools.json` built from the Giga portal CSV export | See §3. No runtime API calls, so no keys in the browser. |
| Offline | `vite-plugin-pwa` (Workbox) for the shell + **OPFS** for the big tile files + **IndexedDB** for data snapshots | Workbox caches small assets well; 37 MB+ range-read archives belong in OPFS, read with `pmtiles.FileSource`. |
| i18n | Own tiny `t()` with JSON dictionaries `en.json`, `si.json`, `ta.json` | Three languages, no plural complexity worth a library; keeps bundle small. |
| Fonts | Self-hosted Noto Sans, Noto Sans Sinhala, Noto Sans Tamil (OFL) | Offline, and covers all three scripts in the UI. |
| Tests | Vitest (units) + Playwright (e2e, driving Edge/Chromium) | Playwright already proven on this machine in phase 1A. |
| Hosting | Static host with HTTP range support and files > 37 MB (GitHub Pages first choice) | No server needed. Cloudflare Pages is ruled out (25 MB per-file limit). Decided in deploy. |

**No database server, no backend.** The app is static files + on-device storage. A single country with ~10k schools fits in memory on any phone.

## 2. Giga data access (finding of this phase)

The Giga API portal (`maps.giga.global/docs/explore-api`) lists 5 APIs:

| API | access | gives | PAE |
|---|---|---|---|
| Country | Public (key held) | id, name, ISO3 | used: Sri Lanka = id 49, `LKA` |
| School location | Public (key held) | Giga ID, name, lon/lat, education level, country | **used** |
| School profile | Private | connectivity, coverage, infrastructure | not available (access can be requested in the portal) |
| School real-time internet quality | Private | daily download speed, latency | not available |
| Giga Meter | Private | raw measurements | not available |

- The API documentation and the download both require a signed-in Giga/UNICEF account. Endpoint docs could not be read without login; per rule 6 the owner downloaded the data instead.
- **Verified contract (CSV export, 2026-11-15)**: `School Giga ID, School Name, Longitude, Latitude, Education Level, Country ISO3 Code, Country Name, School Data Source`. 10,000 rows on page 1 of 2, all `LKA`, 0 duplicate ids, 0 empty names, 0 points outside Sri Lanka; `School Data Source` empty; education level ∈ {Primary and Secondary 5,177; Primary 3,840; Secondary 983}. Page 2 (~100 rows) pending.
- **Consequence:** connectivity status and speeds are **not available**. The app ships every school with `connectivity = "unknown"` and the status/speed UI built against a `ConnectivityProvider` interface, so private data can be plugged in later without UI changes. The recon features that depend on it (speed buckets, week navigator, speed chart) become "ready, no data" states.
- Keys: the app never needs them. They stay in `.env` for an optional Node refresh script (`pipeline/fetch_giga.py`) once the endpoint contract is known.

## 3. Data contracts (instead of SQL)

There is no database, so the "schema" is the set of files the build produces and the on-device stores. TypeScript types are the source of truth (`app/src/data/types.ts` in phase 4).

```ts
// schools.json (generated by pipeline/build_schools.py from data/School_report_*.csv)
interface SchoolsFile {
  version: 1;
  generatedAt: string;          // ISO 8601 UTC
  source: { name: "Giga School location export"; exportedAt: string; files: string[] };
  country: { iso3: "LKA"; gigaId: 49 };
  provinces: AdminArea[];       // OSM admin_level 4 (9 provinces), names en/si/ta
  districts: AdminArea[];       // OSM admin_level 5 (25 districts)
  schools: SchoolRow[];         // compact tuples to keep the file small
}
type SchoolRow = [
  gigaId: string,               // uuid
  name: string,
  lon: number, lat: number,     // 5 decimals (~1 m)
  level: 0 | 1 | 2,             // 0 primary, 1 secondary, 2 primary+secondary
  provinceIdx: number,          // index into provinces, -1 if none
  districtIdx: number
];
interface AdminArea { id: number; name: { en: string; si?: string; ta?: string }; bbox: [number, number, number, number] }

// runtime model (after loading)
interface School {
  id: string; name: string; lon: number; lat: number;
  level: "primary" | "secondary" | "primary_secondary";
  province?: AdminArea; district?: AdminArea;
  connectivity: "connected" | "not_connected" | "unknown";   // "unknown" until a provider exists
  downloadMbps?: { period: "week" | "month"; start: string; value: number }[];
}
interface ConnectivityProvider { name: string; load(ids: string[]): Promise<Map<string, Pick<School, "connectivity" | "downloadMbps">>> }
```

On-device stores:

| store | tech | key | content | eviction |
|---|---|---|---|---|
| app shell | Workbox precache | URL | HTML, JS, CSS, fonts, i18n JSON, glyphs, sprites | replaced on new version |
| `tiles/` | OPFS | file name (`roads.v<hash>.pmtiles`, `base.v<hash>.pmtiles`) | full archives, downloaded once | old hash deleted after successful swap |
| `pae` DB → `snapshots` | IndexedDB | dataset (`schools`) | parsed `SchoolsFile` + `fetchedAt`, `etag` | keep last good |
| `pae` DB → `prefs` | IndexedDB | key | language, theme, accessibility, visible layers, road classes | never |

Every dataset carries `generatedAt`/`fetchedAt`, shown in the UI as data age (README requirement 4).

## 4. Routes and URL state (the "API" of a static app)

Static files served next to the app:

| path | what | size (approx.) | cache |
|---|---|---|---|
| `/data/roads.pmtiles` | roads, z5–14 | 37 MB | OPFS on "download for offline"; range requests online |
| `/data/base.pmtiles` | land, water, admin, places for LK | target < 15 MB | same |
| `/data/schools.json` | §3 | ~0.8 MB raw, ~0.25 MB gzip | IndexedDB snapshot |
| `/data/manifest.json` | file names, hashes, sizes, `generatedAt` | < 1 KB | network-first |
| `/fonts/*`, `/glyphs/*`, `/i18n/*.json` | assets | small | precache |

App routes (hash-free History API, all resolved client-side; Sri Lanka is implicit):

| route | screen (recon) | flow | params |
|---|---|---|---|
| `/` | S09 country view (Sri Lanka) | F02 | `lang`, `layer`, `roads`, `theme` |
| `/school/:gigaId` | S10 school detail | F01, F03 | same |
| `/province/:id`, `/district/:id` | S09 zoomed + filtered | F02, F05 | same |
| dialogs as query (`?panel=layers|filters|share|about|offline`) | S03, S11, S05, S13, new offline panel | F05–F07 | — |

Build-time jobs (no runtime server):

| job | input | output | when |
|---|---|---|---|
| `pipeline/build-roads.ps1` | Geofabrik PBF | `roads.pmtiles` | done (1B); rerun monthly |

## 5. The parts that bite

- **Offline + big files**: 37 MB roads + base must be downloaded explicitly ("Download map for offline", with size and progress), stored in OPFS, and swapped atomically on update. Service workers cannot cache range responses well, which is why OPFS + `FileSource` is used instead of Workbox for tiles. Check storage quota (`navigator.storage.estimate()`) and ask for `persist()`.
- **Sinhala/Tamil on the map**: MapLibre's glyph renderer does not do complex-script shaping, so Sinhala/Tamil map labels would render broken. **Map labels use `name:en` (falling back to `name`)**; all UI text (panels, search, popups) is HTML and renders SI/TA correctly. Revisit if MapLibre adds shaping.
- **Performance on low-end phones**: 10k school points as a GeoJSON source with clustering at low zoom; roads already zoom-tiered (z12 Colombo tile 148 KB gz). Budget: first map paint < 3 s on mid-range Android over 4G; 60 fps pan with roads + schools.
- **Network tiers (README req. 1)**: 4G/5G full map; 3G: skip `base`, roads only from cache; 2G: list/search UI without map. Detect with `navigator.connection` where available, else measure.
- **Data age and staleness**: every view shows when its data was generated; the schools export date comes from the CSV file name.
- **No connectivity data**: UI must not imply schools are offline; "unknown" is shown neutrally (not red).
- **Search**: 10k names, done in memory with accent/case-folded prefix + substring match; Sinhala/Tamil names are not in the export (Latin names only).
- **Attribution / licences**: OSM ODbL attribution always visible; Giga credited as school data source; no Giga branding.
- **Keys**: never bundled; the build fails if `GIGA_` appears in `dist/`.
- **Rate limits / GDPR / multi-tenancy / payments / email**: not applicable (no accounts, no personal data, no server).
